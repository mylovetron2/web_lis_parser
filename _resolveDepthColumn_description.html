2. Source Code đầy đủ

String _resolveDepthColumn(List<String> columnNames) {
  if (columnNames.contains('DEPT')) return 'DEPT';
  if (columnNames.contains('DEPTH')) return 'DEPTH';
  return columnNames.length > 1
      ? columnNames[1]
      : (columnNames.isNotEmpty ? columnNames.first : 'DEPT');
}

4. Thứ tự ưu tiên (Priority Order)

1 Ưu tiên cao nhất: 'DEPT' 
if (columnNames.contains('DEPT')) return 'DEPT';

Nếu có cột tên 'DEPT' → Trả về 'DEPT' ngay lập tức

columnNames = ['TIME', 'DEPT', 'GR', 'DEPTH']
→ Return 'DEPT' (ưu tiên hơn 'DEPTH')
2 Ưu tiên thứ 2: 'DEPTH' 
if (columnNames.contains('DEPTH')) return 'DEPTH';

Nếu không có 'DEPT' nhưng có 'DEPTH' → Trả về 'DEPTH'

columnNames = ['TIME', 'DEPTH', 'GR', 'SP']
→ Return 'DEPTH'
3 Ưu tiên thứ 3: Cột thứ 2 (index 1) 
return columnNames.length > 1 ? columnNames[1] : ...

Nếu không có 'DEPT' hoặc 'DEPTH' nhưng có ít nhất 2 cột → Trả về cột thứ 2

columnNames = ['TIME', 'PROFONDEUR', 'GR', 'SP']
→ Return 'PROFONDEUR' (cột index 1)
Giả định: Cột đầu (index 0) thường là TIME, cột thứ 2 (index 1) thường là DEPTH
4 Ưu tiên thứ 4: Cột đầu tiên 
columnNames.isNotEmpty ? columnNames.first : ...

Nếu chỉ có 1 cột → Trả về cột đó

columnNames = ['DEPTH']
→ Return 'DEPTH' (cột duy nhất)
5 Fallback cuối cùng: 'DEPT' 
... : 'DEPT'

Nếu columnNames rỗng hoàn toàn → Trả về 'DEPT' mặc định

columnNames = []
→ Return 'DEPT' (giá trị mặc định an toàn)
Trường hợp này rất hiếm, có thể chỉ xảy ra khi có lỗi trong việc parse file LIS

6. Tại sao cần hàm này?

6.1. Vấn đề đặt ra

  • Các file LIS khác nhau có thể dùng tên cột khác nhau cho DEPTH
  • Một số file dùng 'DEPT' (viết tắt)
  • Một số file dùng 'DEPTH' (đầy đủ)
  • Một số file dùng tên khác (PROFONDEUR, TEUFE, etc.)
  • Code cần xác định chính xác cột nào là DEPTH để merge dữ liệu

6.2. Giải pháp

Hàm _resolveDepthColumn cung cấp logic thống nhất để:

  1. Tìm cột DEPT hoặc DEPTH nếu có
  2. Fallback về cột thứ 2 nếu không tìm thấy (giả định thông thường)
  3. Xử lý cả edge cases (1 cột, 0 cột)

6.3. Lợi ích

  • ✅ Code DRY: Không phải lặp lại logic này ở nhiều nơi
  • ✅ Tính nhất quán: Cùng 1 logic được dùng cho mergeDepthToTable và normalizeTableData
  • ✅ Dễ maintain: Nếu muốn thay đổi logic ưu tiên, chỉ cần sửa 1 chỗ
  • ✅ Robust: Xử lý được nhiều edge cases

8. So sánh DEPT vs DEPTH

Khía cạnh DEPT DEPTH
Tên đầy đủ Department (sai) / Depth (viết tắt) Depth (đầy đủ)
Độ phổ biến ⭐⭐⭐⭐⭐ (rất phổ biến trong LIS) ⭐⭐⭐ (ít phổ biến hơn)
Ưu tiên 🥇 Cao nhất 🥈 Thứ 2
Tiêu chuẩn LIS format chuẩn Một số biến thể
Lý do ưu tiên DEPT:
  • DEPT là tên chuẩn trong LIS format specification
  • Hầu hết file LIS từ các công ty dầu khí đều dùng DEPT
  • DEPTH thường xuất hiện trong file TXT hoặc các format khác
