🔄 Mô tả hàm mergeDepthToTable

File: lib/services/lis_file_parser.dart

Mục đích: Merge dữ liệu DEPTH từ file TXT vào table data của LIS, đồng thời xử lý cột LSPD (nếu có)

1. Chữ ký hàm (Function Signature)

List<Map<String, dynamic>> mergeDepthToTable({
  required List<Map<String, dynamic>> tableData,
  required String txtContent,
  required List<String> columnNames,
})

Tham số:

Tên Kiểu Mô tả
tableData List<Map<String, dynamic>> Dữ liệu bảng từ LIS file (output của getTableData)
txtContent String Nội dung file TXT chứa TIME, DEPTH, LSPD
columnNames List<String> Danh sách tên cột của table

Giá trị trả về:

List<Map<String, dynamic>> - Dữ liệu bảng đã được merge và chuẩn hóa

2. Mục đích chính

  1. Merge DEPTH từ TXT: Thay thế giá trị DEPTH trong LIS bằng DEPTH từ TXT (chính xác hơn)
  2. Merge LSPD → SPEE: Nếu TXT có cột LSPD, gán vào cột SPEE của LIS
  3. Lọc dữ liệu: Xóa các row không khớp TIME hoặc có TIME NULL
  4. Chuẩn hóa: Sắp xếp và điều chỉnh DEPTH theo step đều đặn
Hàm này sẽ XÓA các row không có TIME khớp với TXT. Số lượng row sau merge thường ít hơn ban đầu.

3. Quy trình xử lý chi tiết

1 Xác định cột DEPTH target 
final targetCol = _resolveDepthColumn(columnNames);
  • Tìm cột DEPTH hoặc DEPT trong columnNames
  • Đây là cột sẽ bị thay thế giá trị
2 Tạo bản sao dữ liệu 
final newTable = List<Map<String, dynamic>>.from(
  tableData.map((row) => Map<String, dynamic>.from(row)),
);

Lý do: Không muốn ảnh hưởng dữ liệu gốc trong memory

3 Parse TXT file 
Map<String, Map<String, String>> timeToData = 
    parseTimeLspdDepthMapFromTxt(txtContent);

Kết quả: Map có cấu trúc:

{
  "12.5": {"DEPTH": "1525.125", "LSPD": "45.2"},
  "13.0": {"DEPTH": "1525.250", "LSPD": "46.1"},
  ...
}
  • Key: TIME (giây) dạng String
  • Value: Map chứa DEPTH và LSPD (nếu có)
4 Duyệt ngược và merge/filter 
for (int i = newTable.length - 1; i >= 0; --i) {
  // Xử lý từng row
}
Duyệt ngược (từ cuối lên đầu) để có thể xóa row an toàn bằng removeAt(i)

4. Logic xử lý từng row

4.1. Lấy giá trị TIME từ cột DEPTH

final rawTime = row['DEPTH'];  // Lưu ý: Dùng cột DEPTH làm TIME!
Đây là thiết kế đặc biệt: Cột "DEPTH" trong tableData LIS thực ra chứa giá trị TIME (milliseconds). Cột này sẽ được THAY THẾ bằng DEPTH thật từ TXT.

4.2. Kiểm tra và xóa row nếu TIME NULL

if (rawTime == null || rawTime == 'NULL') {
  newTable.removeAt(i);
  continue;
}

4.3. Parse TIME thành số

double? timeNum;
if (rawTime is num) {
  timeNum = rawTime.toDouble();
} else {
  timeNum = double.tryParse(rawTime.toString());
}

if (timeNum == null) {
  newTable.removeAt(i);  // Xóa nếu không parse được
  continue;
}

4.4. Chuyển TIME từ milliseconds sang seconds

final timeVal = (timeNum / 1000).toString();
Ví dụ: TIME trong LIS là 12500ms → Chuyển thành "12.5" để khớp với TXT

4.5. Merge DEPTH và LSPD

if (timeToData.containsKey(timeVal)) {
  final data = timeToData[timeVal]!;
  
  // Merge DEPTH
  if (data.containsKey('DEPTH') && 
      data['DEPTH'] != row[targetCol]?.toString()) {
    newTable[i][targetCol] = data['DEPTH'];
  }
  
  // Merge LSPD → SPEE
  if (data.containsKey('LSPD') && row.containsKey('SPEE')) {
    newTable[i]['SPEE'] = data['LSPD'];
  }
} else {
  // Xóa row nếu TIME không khớp
  newTable.removeAt(i);
}
Chỉ merge LSPD nếu:
  • TXT có cột LSPD
  • LIS table có cột SPEE

5. Debug logging

if (newTable.isNotEmpty) {
  print('[DEBUG] After merge: ${newTable.length} rows remaining');
  print('[DEBUG] First row after merge: ${newTable.first}');
  
  // Count TIME NULL
  int nullCount = 0;
  for (var row in newTable) {
    if (row['TIME'] == null || row['TIME'] == 'NULL') {
      nullCount++;
    }
  }
  print('[DEBUG] Rows with TIME NULL: $nullCount/${newTable.length}');
}

6. Chuẩn hóa dữ liệu (normalizeTableData)

normalizeTableData(newTable, columnNames);

Hàm normalizeTableData thực hiện:

1 Xóa tất cả row có TIME NULL 
data.removeWhere((row) {
  final timeValue = row['TIME'];
  return timeValue == null || 
         timeValue == 'NULL' || 
         timeValue.toString().trim().isEmpty;
});
2 Xác định xu hướng DEPTH (tăng/giảm)
  • Đếm số lần DEPTH tăng vs giảm giữa các row liên tiếp
  • Xu hướng chính = xu hướng có count cao hơn
for (int i = 1; i < deptValues.length; i++) {
  if (deptValues[i] > deptValues[i - 1]) increaseCount++;
  if (deptValues[i] < deptValues[i - 1]) decreaseCount++;
}
final isIncreasing = increaseCount >= decreaseCount;
3 Sắp xếp DEPTH theo xu hướng 
data.sort((a, b) {
  final da = double.tryParse(a[deptCol]?.toString() ?? '') ?? 0.0;
  final db = double.tryParse(b[deptCol]?.toString() ?? '') ?? 0.0;
  return isIncreasing ? da.compareTo(db) : db.compareTo(da);
});
  • Nếu xu hướng TĂNG: Sort tăng dần
  • Nếu xu hướng GIẢM: Sort giảm dần
4 Tìm step chính giữa các DEPTH 
for (int i = 1; i < data.length; i++) {
  final prev = double.tryParse(data[i - 1][deptCol]?.toString() ?? '') ?? 0.0;
  final curr = double.tryParse(data[i][deptCol]?.toString() ?? '') ?? 0.0;
  steps.add((curr - prev).abs());
}

// Tìm step xuất hiện nhiều nhất
final stepCounts = <double, int>{};
for (final s in steps) {
  final rounded = double.parse(s.toStringAsFixed(2));
  stepCounts[rounded] = (stepCounts[rounded] ?? 0) + 1;
}
mainStep = stepCounts.entries
    .reduce((a, b) => a.value > b.value ? a : b)
    .key;
5 Ép về step chuẩn 
final allowedSteps = [0.1, 0.5, 1, 2, 5, 10, 20, 50, 100];
double chosenStep = allowedSteps
    .reduce((a, b) => (mainStep - a).abs() < (mainStep - b).abs() ? a : b)
    .toDouble();

Chọn step gần nhất trong danh sách step cho phép

Ví dụ: mainStep = 0.12 → chosenStep = 0.1
mainStep = 0.48 → chosenStep = 0.5
mainStep = 15 → chosenStep = 10
6 Làm tròn DEPTH đầu tiên 
firstDepth = double.tryParse(data.first[deptCol]?.toString() ?? '') ?? 0.0;
firstDepth = double.parse(firstDepth.toStringAsFixed(2));
7 Hồi quy tuyến tính - Tái tính toàn bộ DEPTH 
for (int i = 0; i < data.length; i++) {
  final newDepth = isIncreasing
      ? firstDepth + i * chosenStep
      : firstDepth - i * chosenStep;
  data[i][deptCol] = newDepth.toStringAsFixed(3);
}
Công thức: Nếu xu hướng TĂNG: DEPTH[i] = firstDepth + i × chosenStep Nếu xu hướng GIẢM: DEPTH[i] = firstDepth - i × chosenStep
Tất cả DEPTH ban đầu bị GHI ĐÈ bởi giá trị mới tính theo công thức tuyến tính! Điều này đảm bảo DEPTH đều đặn với step cố định.

7. Ví dụ minh họa

Input:

tableData từ LIS:

[
  {'DEPTH': '12500', 'GR': '45.2', 'SPEE': '10.5'},  // DEPTH = TIME ms
  {'DEPTH': '13000', 'GR': '46.1', 'SPEE': '11.2'},
  {'DEPTH': '13500', 'GR': '47.0', 'SPEE': '12.0'},
  {'DEPTH': '14000', 'GR': '48.5', 'SPEE': '13.1'},
]

txtContent:

TIME    DEPTH   LSPD
12.5    1525.125    55.3
13.0    1525.250    56.1
13.5    1525.375    57.0
14.0    1525.500    58.2

Processing:

  1. Parse TXT → timeToData map
  2. Row 0: TIME = 12500ms / 1000 = "12.5" → Khớp → Merge DEPTH = 1525.125, LSPD → SPEE = 55.3
  3. Row 1: TIME = 13000ms / 1000 = "13.0" → Khớp → Merge DEPTH = 1525.250, LSPD → SPEE = 56.1
  4. Row 2: TIME = 13500ms / 1000 = "13.5" → Khớp → Merge DEPTH = 1525.375, LSPD → SPEE = 57.0
  5. Row 3: TIME = 14000ms / 1000 = "14.0" → Khớp → Merge DEPTH = 1525.500, LSPD → SPEE = 58.2

After merge (trước normalize):

[
  {'DEPTH': '1525.125', 'GR': '45.2', 'SPEE': '55.3'},
  {'DEPTH': '1525.250', 'GR': '46.1', 'SPEE': '56.1'},
  {'DEPTH': '1525.375', 'GR': '47.0', 'SPEE': '57.0'},
  {'DEPTH': '1525.500', 'GR': '48.5', 'SPEE': '58.2'},
]

After normalize:

Giả sử step = 0.125m, firstDepth = 1525.125:

[
  {'DEPTH': '1525.125', 'GR': '45.2', 'SPEE': '55.3'},  // 1525.125 + 0*0.125
  {'DEPTH': '1525.250', 'GR': '46.1', 'SPEE': '56.1'},  // 1525.125 + 1*0.125
  {'DEPTH': '1525.375', 'GR': '47.0', 'SPEE': '57.0'},  // 1525.125 + 2*0.125
  {'DEPTH': '1525.500', 'GR': '48.5', 'SPEE': '58.2'},  // 1525.125 + 3*0.125
]
Dữ liệu đã được merge DEPTH từ TXT, merge LSPD vào SPEE, và chuẩn hóa với step đều đặn!

8. Trường hợp đặc biệt

8.1. Row không khớp TIME

// Nếu TIME trong LIS không có trong TXT → XÓA row
if (!timeToData.containsKey(timeVal)) {
  newTable.removeAt(i);
}
Điều này có thể làm giảm đáng kể số lượng row nếu TXT có ít data hơn LIS

8.2. Row có TIME NULL

Bị xóa ở 2 chỗ:

  • Trong mergeDepthToTable: Xóa ngay khi phát hiện
  • Trong normalizeTableData: Xóa lần nữa để chắc chắn

8.3. TXT không có cột LSPD

if (data.containsKey('LSPD') && row.containsKey('SPEE')) {
  // Chỉ merge nếu cả 2 điều kiện đều đúng
}

Nếu không có LSPD → Chỉ merge DEPTH, không merge SPEE

8.4. LIS không có cột SPEE

Tương tự, không merge LSPD nếu không có cột SPEE đích

10.1. Từ DataTableWidget

Future _mergeByTimeFromTxt() async {
  // Pick TXT file
  FilePickerResult? result = await FilePicker.platform.pickFiles(
    type: FileType.custom,
    allowedExtensions: ['txt'],
  );
  
  String txtContent = utf8.decode(result.files.single.bytes!);
  
  // Merge
  final merged = widget.parser.mergeDepthToTable(
    txtContent: txtContent,
    tableData: tableData,
    columnNames: columnNames,
  );
  
  int matchCount = merged.length;
  
  // Update UI
  setState(() {
    tableData = merged;
  });
}

12. Lưu ý quan trọng

1. Cột DEPTH trong LIS thực ra là TIME!

Trước merge: DEPTH chứa TIME (milliseconds)

Sau merge: DEPTH chứa độ sâu thật (meters)

2. Dữ liệu có thể bị mất!

Các row không khớp TIME với TXT sẽ bị XÓA hoàn toàn

3. DEPTH bị ghi đè hoàn toàn!

Sau normalize, tất cả DEPTH được tính lại theo công thức tuyến tính

4. LSPD chỉ merge nếu cả 2 điều kiện:
  • TXT có cột LSPD
  • LIS có cột SPEE
5. Step chuẩn hóa:

Chỉ chấp nhận: 0.1, 0.5, 1, 2, 5, 10, 20, 50, 100

Step thực tế sẽ được làm tròn về giá trị gần nhất
